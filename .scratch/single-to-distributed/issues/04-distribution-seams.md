# 분산 전환 이음매 확정

Type: grilling
Status: open
Blocked by: 01

## Question

**무엇을 인터페이스 뒤에 숨기고 시작할 것인가.**

"단일로 만들고 나중에 분산으로 넘어간다"는 계획은 넘어갈 지점을 미리 정해두지 않으면 실패한다. 단일 인스턴스에서는 그냥 메모리에 두면 되지만 인스턴스가 늘어나는 순간 깨지는 상태를 식별하고, 각각에 대해 셋 중 하나를 고른다.

- **(ㄱ)** 처음부터 분산 구현으로 간다
- **(ㄴ)** 인터페이스 뒤에 단일 구현을 두고 나중에 갈아끼운다
- **(ㄷ)** 그냥 단일 구현으로 두고 전환 때 다시 짠다

후보:

- **실시간 시청 세션** — 누가 어떤 콘텐츠를 보고 있는가, 시청자 수
- **SSE 연결 레지스트리** — 알림을 보내려면 그 사용자의 연결이 어느 인스턴스에 붙어 있는지 알아야 한다
- **WebSocket 세션과 메시지 브로커** — 콘텐츠 채팅·DM을 같은 방의 다른 인스턴스 사용자에게 전달
- **이벤트 발행** — 단일에선 `ApplicationEventPublisher`, 분산에선 Kafka
- **캐시**
- **인증 세션 무효화** — 강제 로그아웃·계정 잠금이 즉시 반영되어야 하는데 JWT는 스스로 무효화되지 않는다
- **업로드된 프로필 이미지** — 로컬 디스크는 인스턴스가 늘면 깨진다
- **배치 실행** — 인스턴스가 2대면 배치도 2번 돈다

각 항목에 **"이 결정을 나중에 되돌리는 비용"** 을 함께 기록한다. 되돌리기 싼 것은 (ㄷ)이어도 된다. 이음매를 전부 (ㄱ)이나 (ㄴ)으로 덮으면 단일 인스턴스 단계가 사라지고, 그러면 이번 연습의 주제 자체가 없어진다.

이 지도의 중심 티켓이다. 인증·실시간·알림·마일스톤이 모두 여기에 매인다.
