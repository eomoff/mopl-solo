# 실시간 WebSocket 아키텍처 설계

Type: grilling
Status: open
Blocked by: 01, 04

## Question

WebSocket 기반 실시간 기능 3종(같이 보기 세션, 콘텐츠 채팅, DM)의 구조를 정한다.

- **STOMP를 쓸 것인가** — `info.md`의 엔드포인트가 `SUBSCRIBE /sub/...`, `SEND /pub/...` 형태라 STOMP를 전제한 것으로 보인다. 확인하고 확정한다.
- **WebSocket 인증** — 클라이언트가 연결 시 액세스 토큰을 헤더에 넣는다. Spring WebSocket Security로 **어느 시점에**(핸드셰이크 / CONNECT 프레임) 인증할 것인가. 토큰이 연결 도중 만료되면?
- **시청 세션의 생명주기** — JOIN/LEAVE를 무엇으로 판정하는가. 연결이 비정상 종료되면? 브라우저 탭을 여러 개 열면? **시청자 수는 사용자 기준인가 연결 기준인가.**
- **채팅 메시지는 저장하지 않는다**(`info.md` 명시). 그러면 늦게 들어온 사람에게는 아무것도 안 보이는 것이 맞는가.
- **DM의 두 경로** — 활성 대화는 WebSocket, 다른 대화는 SSE. 한 메시지가 두 경로로 **중복 전달되지 않게 하는 기준**은 무엇인가. "활성"을 누가 판정하는가.
- 위 전부에 대해 **인스턴스가 2대일 때 무엇이 깨지는가**.
