# 12주 마일스톤 구획

Type: grilling
Status: open
Blocked by: 04, 05

## Question

12주를 어떻게 끊을 것인가. 이음매와 도메인 모델의 결정을 받아 실제 순서를 정한다.

- **단일 인스턴스 완성까지 몇 주** — 그리고 "완성"의 기준은 무엇인가. 프론트가 붙어서 도는 것?
- **어느 기능부터** — 인증 → 콘텐츠 → 평점·플레이리스트 → 관계 → 실시간 → 알림 순으로 가로로 쌓을 것인가, 아니면 세로로 얇게 한 흐름을 끝까지 뚫고 넓혀갈 것인가.
- **분산 전환을 언제 시작할 것인가** — 모든 기능이 끝난 뒤인가, 아니면 일부 기능만 있을 때 한 번 겪어보고 나머지를 분산 전제로 만들 것인가. **후자가 이번 연습의 주제에 더 가까울 수 있다.**
- **AWS를 언제 처음 올려볼 것인가** — 마지막에 몰면 반드시 터진다.
- 12주 중 얼마를 버퍼로 남길 것인가.
---

**[콘텐츠 수집 배치 설계]가 넘긴 일정 항목**

- **최초 백필은 TMDB `popularity` 상위 30,000건**이며 20 req/s에서 **약 25분**이 걸린다. 하루에 여러 번 돌릴 수 있으므로 일정의 병목이 아니다.
- **스포츠는 시간이 곧 데이터다.** 무료 키의 `eventsday`가 하루 3건을 주므로, 정기 Job을 **일찍 켜둘수록** 경기 데이터가 쌓인다. 12주 후반에 시작하면 수십 건에 그친다 — **스포츠 수집 Job은 앞쪽 마일스톤에 배치해야 한다.**
- TMDB 정기 Job은 익스포트 발행 시각(**KST 17:00**)에 매인다.
