# 스포츠 콘텐츠를 목적지에 둘 것인가

Type: grilling
Status: resolved

## Question

[The Sports DB API 조사]가 이 질문을 열었다. 조사 전에는 "스포츠도 그냥 수집하면 되는 것"이었으나, 실측 결과 **비용·계약·데이터 세 방향에서 동시에 걸린다.**

- **비용** — 무료 키로는 배치가 불가능하다(전 세계 하루 3경기, 리그 목록조차 열거 불가). 실질 최소선이 **$9/월**이다. AWS를 상시로 띄우지 않기로 한 이 노력에서, 12주 동안의 구독료를 감수할 것인가.
- **계약** — `ContentDto`에 **날짜 필드가 없다.** 경기 시작 시각을 놓을 자리가 없고 "다가오는 경기" 정렬이 불가능하다. `description`은 required인데 실측 90건 중 1건만 채워져 있어 **우리가 합성해야 한다.**
- **데이터** — 증분 수집이 없고, 경기는 생성 후 변하며(점수·취소), 스포츠끼리도 균질하지 않다(팀 null). 한국어가 전혀 없다.

선택지:

- **(ㄱ) 그대로 포함** — 구독하고, 부속 테이블을 만들고, `description`을 합성한다. `info.md` 요구사항을 온전히 만족한다.
- **(ㄴ) 무료 티어로 축소 포함** — 소수의 리그·경기만 넣어 sport 타입이 "동작하는 것"만 보인다. 배치의 학습 가치는 TMDB에서 이미 확보된다.
- **(ㄷ) 이번 목적지에서 제외** — 콘텐츠를 영화·드라마로 한정한다. 계약의 `sport` enum은 남기되 데이터를 넣지 않는다.

**판단 기준은 "이 연습의 주제에 기여하는가"다.** 이 노력의 주제는 단일→분산 전환이지 외부 API 통합의 폭이 아니다. 스포츠가 그 주제에 무엇을 더하는지가 (ㄱ)의 비용을 정당화해야 한다.

이 결정이 [도메인 모델 확정]의 콘텐츠 모델 형태와 [콘텐츠 수집 배치 설계]의 Job 분할, [외부 API 키 발급]의 실행 여부를 모두 바꾼다.

## Answer

**(ㄴ) 무료 티어로 축소 포함.** 사용자 결정: "외부 api는 모두 무료로 사용할거야."

### 이 결정이 뜻하는 것

무료 키의 실측 상한이 그대로 스포츠 콘텐츠의 상한이 된다.

- `eventsday` → **전 세계 통틀어 하루 3경기**
- `eventsseason` → 380경기 시즌 중 15개
- `all_leagues` → 10개(전부 유럽 축구)

따라서 **스포츠는 "동작하는 것을 보여주는 수준"으로만 존재한다.** 콘텐츠 목록에 몇 건이 뜨고, 평점·플레이리스트·같이 보기가 sport 타입에서도 작동하는 것까지가 도달점이다. 의미 있는 규모의 경기 데이터는 이번 목적지 안에 없다.

이 축소를 감수할 수 있는 근거는 목적지에 있다 — 이 노력의 주제는 **단일→분산 전환**이지 외부 API 통합의 폭이 아니다. 배치·증분 수집·실패 처리의 학습 가치는 [TMDB API 조사]가 확인한 규모(영화 익스포트 1,238,234줄)에서 이미 충분히 확보된다. 스포츠는 **"타입이 여러 개인 콘텐츠 모델"이라는 설계 문제**를 제공하는 것으로 제 몫을 한다.

### 그래도 남는 작업

무료라고 해서 설계가 쉬워지지는 않는다. 다음은 그대로 남는다.

- `ContentDto`에 날짜 필드가 없어 경기 시작 시각을 놓을 자리가 없는 문제 → [도메인 모델 확정]
- `description`이 required인데 실측 90건 중 1건만 채워져 오는 문제(합성 필요) → [도메인 모델 확정]
- 증분 수집 수단이 없어 `idEvent` upsert가 유일한 경로인 점 → [콘텐츠 수집 배치 설계]
- 429가 JSON이 아니라 Cloudflare 텍스트인 점 → [콘텐츠 수집 배치 설계]

### 파생 결정

[외부 API 키 발급]이 **무료 키 확보로 축소**된다. TheSportsDB는 공개 테스트 키 `123`을 쓰므로 발급 절차 자체가 없고, TMDB만 무료 가입이 필요하다. 결제·구독 단계가 사라진다.
