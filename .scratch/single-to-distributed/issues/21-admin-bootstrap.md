# 어드민 계정 초기화 규칙

Type: grilling
Status: open
Blocked by: 06

## Question

`docs/info.md`가 요구한다 — **"초기화: 서버 시작 시 어드민 계정을 자동으로 초기화합니다."** 한 줄뿐이고 나머지는 전부 열려 있다.

[인증·인가와 토큰 무효화 설계]가 인증의 나머지를 모두 닫았지만(리프레시 토큰 저장·회전, Redis 무효화 목록, 임시 비밀번호를 사용자 행에, 탈퇴 미구현) **최초의 어드민이 어떻게 존재하게 되는가**는 다루지 않았다. 계약에 어드민 전용 경로가 없어 **인가가 경로가 아니라 메서드 수준에서 갈리므로**, 어드민이 하나도 없으면 권한 변경·계정 잠금·콘텐츠 등록 경로 전체가 아무도 통과할 수 없는 상태가 된다.

- **Q1. 자격 증명은 어디서 오는가.** 저장소가 **public**이라 비밀번호를 코드나 `application.yml`에 둘 수 없다. [로컬 개발·분산 환경 구성]이 `.gitignore`에 `.env`를 추가해 뒀다. 그러면 AWS에서는 — [AWS 배포 형상 확정]이 **장기 키를 시크릿에 넣지 않는다**는 원칙으로 OIDC를 택했는데, 어드민 비밀번호는 어떤 경로로 들어가는가.
- **Q2. 멱등성.** 이미 있으면 무엇을 하는가. 건너뛰는가, 비밀번호를 매 시작마다 설정값으로 되돌리는가(운영에선 위험, 연습에선 편리), 아니면 없을 때만 만드는가.
- **Q3. 인스턴스가 2대면 초기화도 2번 돈다.** [분산 전환 이음매 확정]이 **배치 중복 실행**을 7번 이음매로 잡아 "(ㄷ) 전환 시점에 잠금 추가"로 미뤘는데, 어드민 초기화도 같은 모양의 문제다. **같은 이음매로 묶을 것인가, 이메일 unique 제약이 잡아주는 것으로 충분하다고 볼 것인가.** 후자라면 두 번째 인스턴스가 받을 제약 위반 예외를 정상 경로로 삼켜야 한다.
- **Q4. 어디서 실행하는가.** `ApplicationRunner` / `ApplicationReadyEvent` / DB 마이그레이션(Flyway) 중 무엇인가. 마이그레이션이면 Q3이 통째로 사라지지만 비밀번호 해시를 SQL에 박아야 한다.
- **Q5. 검증 형상과의 충돌.** [AWS 배포 형상 확정]은 RDS를 **스냅샷 후 삭제·복원**한다. 복원된 DB에는 어드민이 이미 있다. Q2의 답이 이 시나리오에서도 성립하는지 확인한다.
